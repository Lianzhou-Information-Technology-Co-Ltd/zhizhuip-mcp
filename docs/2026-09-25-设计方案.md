# zhizhuip-mcp 设计方案

- 日期：2026-09-25
- 状态：已实现；2026-10-09 接入动态不限流量（带宽）；原实施计划见 `2026-09-25-实施计划.md`
- 范围：蜘蛛 IP（zhizhuip.com）对外 API（`externalapi`）的 MCP 适配层
- 上游文档：<https://develop.zhizhuip.com/llms.txt>（Apifox 导出，每页内嵌 OpenAPI 3.0.1 YAML）
- 后端仓库：`ip-proxy`，模块 `application/externalapi`

## 1. 背景与目标

把已经对外开放的 `externalapi` 接口以 MCP 形式提供给 AI 客户端（Claude Code、Claude Desktop 等），让模型能查询子账号、流量、价格、库存，并在用户确认后执行下单、续费、改配置等操作。

MCP 服务器只是一个 HTTP 客户端：业务逻辑、参数校验、鉴权、扣费全部仍在 PHP 后端执行，本项目不改后端任何代码。

### 已确认的决策

| 项 | 决定 |
|---|---|
| 项目形态 | 独立仓库 `zhizhuip-mcp`，TypeScript，官方 MCP SDK v2（`@modelcontextprotocol/server` 2.x），Node ≥ 20，仅 stdio |
| 范围 | 文档站 41 条 `/externalapi/` 路径。不纳入 `/api/route_setting/*`（IPAPI 白名单 5 接口 10 页：不在 externalapi，且 api 模块不认 API Key）；不做「IPAPI 提取说明」（公开提取接口，不走 externalapi）；不暴露 `tool/deleteSubAccountWhiteList`、`tool/setSubAccountWhiteList` |
| 鉴权 | 只认 API Key，放请求头 `token`。所有工具参数剔除 `access_token`，不管接口页怎么写 |
| 产品标识 | MCP 层一个 `product` 枚举（8 个值），运行期展开成后端的 `type`/`status`/`native`/`version`/`is_month` 组合，或动态带宽的 `product_type_id=11` |
| 拆分 | `createProductOrder` 拆成动态流量、时长 IP、动态带宽三个工具；续费与退单也按新旧产品拆分；列表合并，其他同路径按现有规则合并 |
| HTTP 动词 | 只读 GET，其余 POST；文档里的 PUT/DELETE 一律 POST（后端全部用 `param()` 读参，已核实） |
| 参数类型 | 子账号 id 类参数一律 string，数组元素也是；分页、数量、时长、带宽等仍 integer |
| 环境变量 | `ZHIZHUIP_TOKEN`、`ZHIZHUIP_BASE_URL`、`ZHIZHUIP_TIMEOUT_MS`、`ZHIZHUIP_CONFIRM_QUIET_MS` |
| 分发 | git clone 本地构建 + 发布 npm；包名 `zhizhuip-mcp`，服务名 `zhizhuip`，`setup` 子命令保留 `--npx` |
| 预约 IP | `bookingIPArea` 做成需确认的普通写工具，不标 destructive |
| 主账号切换 token | `device/userListEnabled` 做成只读工具 `main_account_switch_token` |
| 文档 | `docs/2026-09-25-设计方案.md`、`2026-09-25-实施计划.md`、`2026-09-25-联调记录.md`；不自动 git commit |

### 非目标

- 不覆盖前台 `api` 模块的接口。
- 不做 OAuth、多用户远程服务、账号密码换 token 的旧鉴权方式。
- 不在 MCP 层重做参数校验与业务规则，后端返回什么错误就透传什么。

## 2. 总体架构

```
Apifox 文档站 ──(开发期: npm run sync-docs)──▶ spec/pages/**/*.md + spec/overrides.yaml ──▶ spec/tools.json
                                                                                              │
                                                                                    (运行期: 只读本地文件)
                                                                                              ▼
AI 客户端 ◀── stdio ──▶ zhizhuip-mcp [--readonly] [--yes] ── HTTPS ──▶ https://www.zhizhuip.cc/externalapi/*
                                                                         header: token
```

- 生成是开发期动作，输出提交进仓库；运行期不联网拉文档，启动即用。
- 默认注册全部 44 个工具，`--readonly` 按只读标注过滤出 21 个，`--yes` 关闭写操作确认。
- 每个请求附带请求头 `User-Agent: zhizhuip mcp` 和参数 `is_mcp_send=1`。蜘蛛后端目前不识别这个标记，留着是为了后端将来加识别时不用改 MCP，零成本。
- 每个请求固定带 `Accept-Language: zh-CN`：不带时运行时默认发 `*`，后端开了按语言头自动切换语言，解析不了 `*`，所有接口都返回空的 HTTP 500（2026-09-26 联调发现）。

### 技术选型

| 用途 | 选择 | 说明 |
|---|---|---|
| MCP 协议 | `@modelcontextprotocol/server` 2.x | 官方 SDK，stdio 入口 `serveStdio`，兼容 2025 与 2026 两代客户端协议；测试用 `@modelcontextprotocol/client` |
| 参数校验 | SDK 内置：`fromJsonSchema()` + Ajv | 生成好的 JSON Schema 原样注册，`tools/list` 与文档一致；不引入 zod，不做二次转换 |
| 表单编码 | 自写 `toForm()`，基于 `URLSearchParams` | 约 10 行产出 PHP 括号格式，不加依赖 |
| YAML 解析 | `yaml` | 仅同步脚本使用，运行期不 import |
| 测试 | vitest | 单元测试、以真实文档页为输入的快照测试、起本地假后端的 stdio 端到端测试 |

## 3. 文档到工具的生成规则

同步脚本兼容 `api-数字.md` 与 `数字e0.md` 接口链接。2026-10-09 清单共 130 个接口页：排除 10 个 `/api/` 页面，以及“对外接口”分组下已有正式产品分组的 5 个重复页，存档 115 个页面。未知且不重复的分组仍报错，避免漏收新接口。动态带宽的 Session 页与现有说明内容相同，继续共用一个资源。

### 3.1 产品表

产品表是生成脚本里的常量，同时写进每个带 `product` 参数的工具的 tools.json 条目，运行期不需要额外文件。枚举值与 `spec/pages/` 目录名一字不差。

| product | 中文标签 | 文档站分组（页面 `tags`） | 展开成的后端参数 |
|---|---|---|---|
| `dynamic-no-expiry` | 动态住宅流量（永久） | 用户IP子账号管理/动态住宅流量子账号(永久) | `type=0, status=0, is_month=0` |
| `dynamic-monthly` | 动态住宅流量（期限） | 用户IP子账号管理/动态住宅流量子账号(期限) | `type=0, status=0, is_month=1` |
| `dynamic-bandwidth` | 动态住宅不限流量（带宽） | 用户IP子账号管理/动态住宅不限流量 | `product_type_id=11` |
| `static-standard` | 静态住宅（非原生） | 用户IP子账号管理/静态住宅（非原生）时长子账号 | `type=1, status=1, native=0` |
| `static-native` | 静态住宅（原生） | 用户IP子账号管理/静态住宅（原生）时长子账号 | `type=1, status=1, native=1` |
| `static-isp-native` | 静态住宅（运营商原生） | 用户IP子账号管理/静态住宅（运营商原生）时长子账号 | `type=1, status=1, native=2` |
| `static-ipv6` | 静态住宅（IPv6） | 用户IP子账号管理/静态住宅（IPV6）时长子账号 | `type=1, status=1, native=1, version=6` |
| `datacenter` | 数据中心 | 用户IP子账号管理/数据中心时长子账号 | `type=2, status=1` |

无产品的分组：`工具管理` → 目录 `tool`，`用户管理` → 目录 `user`。分组名比对前去掉空白；文档站新增分组时生成报错，补一行即可。

后端参数含义（供理解，不进工具 schema）：`type` 套餐类型 0 动态住宅 / 1 静态住宅 / 2 数据中心；`status` 计费模式 0 按流量 / 1 按时长；`native` 0 非原生 / 1 原生 / 2 运营商原生；`version` 6 = IPv6；`is_month` 0 = 永久、1 = 流量限时（期限）。两个动态流量产品都显式发 `is_month`（文档站 2026-09-26 起永久页也写了固定为 0），后端不传时当 0，效果相同。

### 3.2 sync-docs

1. 抓取 `llms.txt`，匹配 `api-数字.md` 和 `数字e0.md` 接口链接；找到的页数少于 100 视为格式变化，中止。
2. 下载全部接口页并解析。路径不在 `/externalapi/` 下的页（目前是 10 页 IPAPI 白名单）不落盘，打印一行列出；普通说明页与 schema 页跳过；“对外接口”分组下的重复页以正式产品分组为准。
3. 落盘位置 `spec/pages/<分组目录>/<控制器>-<方法>.md`；同一分组同一接口多页时文件名带 Apifox 页面 id（目前没有）。未命中的旧文件删除。
4. Session 说明页 `3837564m0.md`（永久、期限与不限流量三页内容相同，取永久这页）另存为 `spec/dynamic-proxy-session.md`。
5. 结束后调 build-spec。

### 3.3 合并规则（`scripts/lib/merge.ts`）

1. **按 `path` 合并**，忽略文档中的动词。同一路径在不同产品目录下各有一页，参数集不同。
2. **产品来自分组**，不靠参数描述里的"此处固定为 N"。页里写的固定值只用来与产品表交叉核对，对不上就打印警告；由 overrides 的 `products` 显式指定该工具的产品列表。已知会触发警告的：子账号白名单两页挂在"永久"分组却写 `is_month` 固定为 1，overrides 指定两个动态产品。
3. **`product` 参数**：`type`、`status`、`native`、`version`、`is_month`、`product_type_id` 从参数表里拿掉，换成一个必填的 `product` 枚举，枚举值就是该路径有页的那些产品，按产品表顺序排；描述为"产品：dynamic-no-expiry=动态住宅流量（永久），…"。只有一个产品的工具（IPv6 购买、IPv6 续费、动态带宽的四个写工具）不出 `product` 参数，固定参数写进工具的 `fixed`。无产品分组的页参数照文档保留（优惠券列表的 `type`、`status` 是真正的筛选条件）。
4. **参数取并集**：query 参数与表单 body 参数合成一张表。必填规则：在所有变体中都必填才标必填；否则可选，并在描述中注明"产品 dynamic-monthly 下必填"。
5. **括号参数转结构**：`content[0][id]` → `content: object[]`；`content[0][ids][0]` → `content[].ids: string[]`；`accounts[0][account]` → `accounts: object[]`；`specifyIps[0][ipStr]` → `specifyIps: object[]`；`sub_accounts[]`、`sub_accounts[0]`、`searchArr[0]` → 数组。
6. **动词**：工具标注为只读则 GET，否则 POST。
7. **overrides.yaml** 按路径覆盖：工具名、中文描述、只读与破坏性标注、产品列表、参数类型/描述/枚举/必填、拆分规则、忽略路径、派生工具。文档缺陷兜底也放这里，带"文档缺陷兜底"注释，文档修好后删除。
8. 其余规则：描述去 HTML 标签；同一参数一页 array 一页标量时标量优先；所有对象 `additionalProperties: false`。
9. 输出 `spec/tools.json`（MCP 工具形态：名称、标题、描述、JSON Schema、标注、路径、动词、固定参数，以及可选字段 `products`：枚举值 → 展开参数）。脚本结束时打印与上一版的差异，供人工审阅后提交。

### 参数要点

- 动态带宽产品用 `product_type_id=11` 分流，不能附加旧产品的 type/status 组合。列表 `sub_account_list` 支持 `product=dynamic-bandwidth`，保留 page/pagesize 必填契约；四个专用写工具固定产品，不暴露 product 参数。续费、升级、退单的 `sub_account_id` 取 `rows[].sub_account` 并传字符串，不取本地 id。入口国家 US/DE/SG、时长档 1/2/3、带宽整数最低 10 Mbps。价格接口暂不含动态带宽报价，费用与适用券先在网站核实。

- `pagesize` 的上限照各页文档写，生成器不统一追加：子账号列表与批量限流查询最大 100，已购流量套餐记录后端不限。
- 子账号 id 类参数一律 string：`id`、`ids`、`subAccount`、`subAccounts`、`account`、`accounts`、`sub_accounts[]`、`sub_account_id`、`content[].id`、`content[].ids[]`。`page`、`pagesize`、`num`、`timelen`、`changeInterval`、`bandwidth_num`、`trend_type`、`startTime`、`endTime` 保持 integer。
- `order_buy_dynamic` 参数：`product`（两个动态产品）、`num`、`conpon_id`、`bill_timelen`（仅 dynamic-monthly 有效）。
- `order_buy_time_ip` 参数：`product`（静态 3 + datacenter）、`num`、`country`、`timelen`、`agree`、`city`、`conpon_id`、`verder_order_id`、`use_random_username`、`use_ip_port`、`ip_str`、`exclude_ip_str`、`bandwidth_num`、`remark`、`specifyIps[]{ipStr,count}`。描述注明后端规则：`num` 1 到 300，数据中心单笔不超过 50 且不支持 7 天档；`agree`、`country` 按文档标必填。
- `order_renew` 参数：`product`、`content[]{ids[],country,timelen,renew_with_bandwidth}`、`conpon_id`。描述注明一次最多 200 条。
- `coupon_list` 的 `type`（0 动态住宅 / 1 静态住宅 / 2 数据中心）和 `status`（静态住宅与数据中心固定 1）照文档给枚举。
- `country`、`country_code` 一律为 ISO 3166-1 二字码，如 `US`，在描述中说明。

## 5. 鉴权与配置

| 环境变量 | 必填 | 默认值 | 说明 |
|---|---|---|---|
| `ZHIZHUIP_TOKEN` | 是 | 无 | 网站 API Keys 页面生成的 API Key（`sk-` 开头 35 位），永久有效，每账号最多 20 个 |
| `ZHIZHUIP_BASE_URL` | 否 | `https://www.zhizhuip.cc` | 便于指向测试环境 |
| `ZHIZHUIP_TIMEOUT_MS` | 否 | `30000` | 单次请求超时 |
| `ZHIZHUIP_CONFIRM_QUIET_MS` | 否 | `10000` | 确认码发出后的静默期，见第 7 节 |

- token 放请求头 `token`。工具参数里没有 `access_token`。
- 收到 HTTP 401（`{code:401,msg:"API Key 无效或已删除"}` 或 `"请先登录"`）时，工具返回明确提示：API Key 无效，请到网站 API Keys 页面核对或重新生成并更新 `ZHIZHUIP_TOKEN`。
- token 不写日志、不落盘。stdio 模式下 stdout 是协议通道，所有日志只走 stderr。

## 6. 请求与响应映射

- 运行期先把 `product` 展开：`{...其余参数, ...tools.json 里该工具 products[product], ...fixed, is_mcp_send: 1}`，再交给表单编码。
- GET：参数进 query string。POST：`application/x-www-form-urlencoded`，`toForm()` 生成 `content[0][ids][0]=…` 这类 PHP 括号格式。
- 参数类型由 SDK 按 JSON Schema 在调用前校验，不符合时直接返回 `isError` 的校验提示，不请求后端。
- 响应统一为 `{code, msg, time, data}`：`code === 1` 返回 `{code, msg, data}` 的 JSON 文本；其它 `code` 为 `isError: true`，文本为 `msg`；非 JSON 或 HTTP 5xx 带状态码与前 200 字符正文。
- 后端限流"访问频繁,请稍后再试!"原样透传，并注明限额：每接口每 IP 30 秒内 300 次，带宽类接口 60 次。

## 7. 安全与副作用标注

- 只读工具：`readOnlyHint: true`。
- 删除与扣费工具：`destructiveHint: true`，`idempotentHint: false`；描述首句写明"会从账户余额扣费"或"不可恢复"。`ip_booking`、`order_refund_apply`、改配置类工具是普通写操作，不标破坏性。
- 写操作确认（`src/confirm.ts`）：23 个非只读工具的处理器由 `withConfirm` 包装。客户端声明了 elicitation 能力（2025 版协议看连接初始化时的能力，2026 版看每个请求信封里的客户端能力）就返回 `inputRequired`，客户端弹出操作预览，用户 accept 且勾选确认才调后端。用户拒绝、关闭弹窗、未勾选，以及客户端声明支持却不显示弹窗（Claude Code 的 VS Code 插件目前如此）的情况，都不当作最终拒绝，而是退到确认码，由模型在对话里再问用户一次；不支持 elicitation 的客户端直接走确认码。确认码路径：第一次调用只返回预览和一次性 `confirm_token`（用工具名加参数的 SHA-256 指纹绑定，5 分钟有效，用一次作废，参数变了作废），发出后有静默期（默认 10 秒，`ZHIZHUIP_CONFIRM_QUIET_MS` 可调），静默期内带码调用返回"还不能用"、不消费、生效时间再顺延，挡的是模型拿到码不问用户就重调；带确认码的调用直接校验，不再弹窗。`--yes` 关闭确认。写工具的 schema 注册时多一个可选 `confirm_token`，`tools.json` 本身不含。预览由工具标题、描述首句、逐个参数拼成，`product` 显示中文标签，不查价不查余额。
- 默认模式启动时在 stderr 打印一行提示，说明含扣费与删除操作且执行前会确认，只查询请加 `--readonly`。

## 13. 后端事实（已对照 ip-proxy 源码核实，2026-09-25）

- API Key：`sk-` + 32 位小写十六进制。`externalapi/library/ApiKeyAuth.php` 挂在 `externalapi/controller/Base.php` 的 `_initialize`，请求头 `Token` 或参数 `access_token` 都收；Key 无效、已删除、账号停用都返回 HTTP 401 `{code:401,msg:"API Key 无效或已删除"}`；没带 token 时由 common\Api 返回 401（msg 是 Please login first 的翻译键，externalapi 没有语言包，可能原样返回英文）。api 模块没挂这个鉴权，用 Key 调 `/api/*` 会 401。
- 限流 `requestAccess()`：externalapi Base 300 次、Bandwidth 控制器 60 次，按 IP + 接口路径计数，窗口 30 秒；超限 HTTP 200 `{code:0,msg:"访问频繁,请稍后再试!"}`。
- 参数读取：全部控制器用 `request->param()`（GET、POST、PUT 都收），没有 `put()`/`delete()`；只有 `Device::accountList` 有 5 个参数（`user_setmeal_id`、`countryList`、`state`、`city`、`remark`）用 `request->get()` 只从 query 读，所以只读工具必须走 GET。
- 响应：成功 `{code:1,msg,time,data}`；业务错误 HTTP 200 `{code:0,msg,data:null}`。
- `createProductOrder` 校验：`type` in 0,1,2；`status` in 0,1,2；`native` 在 type=1 时必填；`num` 1 到 300；数据中心 `num` ≤ 50 且 `timelen` ≠ 0；下单前要求账号已完成邮箱或手机验证与实名验证（`isverify`，IPv6 与测试 IP 下单同样要求）；`agree` 默认 SOCKS5；`country` 默认 US；5 秒内相同参数重复请求被拒。
- `createProductOrder` 动态流量：`bill_timelen` 在 `is_month=1` 时必填且只能 1/2/3（2026-09-26 修正了原来少写 `|` 的校验规则），永久套餐不传；schema 里保持可选，靠后端在期限套餐下强制。
- `renewOrder`：`content` 数组，`type` in 1,2，一次最多 200 条；不回写 `is_renew`，只按本次的 `renew_with_bandwidth` 算价。所以续费工具不需要在调用前查子账号当前设置来补参数，直接透传。
- `renewOrderIpv6`：一次最多 2000 条；`timelen` 为 0 时报"timelen必须在 1,2,3,4 范围内"，所以 IPv6 续费没有 7 天档（IPv6 购买有）；优惠券被强制清空。
- `createIpv6Order`：优惠券被强制清空（`conpon_id` 置 false），所以 IPv6 购买不暴露优惠券参数。
- `createTestOrder`：按账号的测试配置限额，本月已建与已删的测试单都计数，额度用完或本次数量超过剩余额度直接拒绝；额度内每单按配置的金额从余额扣款。
- `bookingIPArea`：写 `fa_booking_area` 一条预约记录并给超级管理员建待办，不扣费、不建子账号；`num` 1 到 1000。
- `userListEnabled`：按 `is_month` 取动态主账号，到上游代理平台读主账号信息，token 为空时生成 8 位随机值回写，返回 `{token}`。
- `getOriginCustomPriceInfo` 与 `getUserCustomPriceInfo` 都在 Tool 控制器。
- 后端不识别 `is_mcp_send`。数据库开了字段严格模式，把请求参数整包写库的地方会因为它报 fields not exists；`accountLimitFlowSet` 首次写入原来就是这样，2026-09-26 后端改为只写表里的字段。
